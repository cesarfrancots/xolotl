# Xolotl v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Xolotl v1: a small Rust terminal coding agent for GLM 5.3 Flash. It has an inline REPL plus a headless mode, seven tools, three permission modes, and disk-backed context with two-stage compaction that never loses history.

**Architecture:** One binary crate with eight modules.
- Fixed plumbing: `llm` (model client), `store` (session store), `tools`, `perms`, `ui`, `agent` (the loop) and `main` (CLI).
- `policy.rs` holds everything that decides what the model sees. It must keep the signatures listed in the spec (§5.1) so a v2 optimizer can rewrite it safely.
- Every event is appended to `events.jsonl`, which is the source of truth. The prompt is rebuilt from it on every model call.

**Tech Stack:** Rust 1.95 (edition 2024). Crates: `ureq` 3, `serde` (derive), `serde_json`, `ignore`, `globset`, `regex`, `reedline`, `crossterm`, `ctrlc`.

**Spec:** `docs/superpowers/specs/2026-10-04-xolotl-v1-design.md`. Read it alongside this plan; section numbers below (§n) refer to it.

## Global Constraints

- **Toolchain:** stable Rust 1.95, edition 2024, single binary crate named `xolotl`.
- **Dependencies:**
  - Only `ureq` 3, `serde` (features `derive`), `serde_json`, `ignore`, `globset`, `regex`, `reedline`, `crossterm` (the same version `reedline` uses — check with `cargo tree -i crossterm`, one copy only) and `ctrlc`.
  - No async runtime, no clap, no TUI framework, no tokenizer, no tempfile.
- **Platforms:** Windows 11 is the primary platform. The crate must also compile on Linux/macOS (`#[cfg(windows)]` branches where behavior differs).
- **API key:** read only from the environment variable named by `api_key_env` (default `ZAI_API_KEY`). Never write it to disk, into any event, or into logs.
- **Defaults:**

  | Setting | Value |
  |---|---|
  | `base_url` | `https://api.z.ai/api/paas/v4` (or the M0-confirmed URL) |
  | `model` | `glm-5.3-flash` |
  | `context_budget` | `200000` |
  | `mode` | `writes` |
  | `temperature` | `1.0` |
  | `top_p` | `0.95` |
  | `reasoning_effort` | `"max"` |

- **Events:** append-only, `seq` = 1-based line number, flushed after every event.
- **Truncation:** every string truncation goes through `tools::clip` / `tools::clip_tail`, which are char-boundary safe. Never slice `&s[..n]` directly.
- **Tool failures:** a tool failure returns `ToolOut { ok: false, .. }`. Tools never panic.
- **Model-visible text:** prompts, stubs, the table of contents and the summary layout live in `src/policy.rs`, with the contract signatures from spec §5.1.
- **Git:**
  - Work on branch `feat/xolotl-v1`, cut from `docs/v1-spec`. Never commit to `main`.
  - Every commit message ends with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Commit steps below show only the subject line.
- **Tests:**
  - Unit tests live in `#[cfg(test)] mod tests` inside each module. There is no `tests/` directory, because the crate is binary-only.
  - Temp directories come from `store::test_dir(tag)`.
  - Shell-dependent tests return early when `resolve_shell()` isn't `Shell::Bash`.

## Review Focus

1. **One request that outgrows the budget.** A single request can turn into 100+ tool calls. Stage 2 must still free space by cutting mid-turn, and must keep the request verbatim. Pinned by `stage2_cut_mid_turn_single_long_request` (Task 9) and `single_long_request_compacts_mid_turn` (Task 12).
2. **Multi-byte UTF-8 at any truncation point.** Cargo's box-drawing characters, non-English text and emoji must never cause a panic. Pinned by `clip_never_splits_chars` (Task 4) and `cap_output_multibyte_boundary` (Task 8).
3. **Commands that wait for input.** Bare `cat`, a Python REPL, or git opening an editor must return promptly, not hang until the timeout. The same goes for background processes that keep a pipe open. Pinned by `stdin_is_closed` and `background_process_does_not_hang` (Task 5).
4. **Non-UTF-8 files passed to `edit`.** These must be refused, with the file left byte-for-byte unchanged. Pinned by `edit_refuses_non_utf8` (Task 4).
5. **A network drop after text has already streamed.** It must not be silently retried, since that would duplicate output. It must be recorded, and the user returned to the prompt. Pinned by `retry_policy` (Task 2) and `llm_error_recorded` (Task 11).

- [ ] **Step 3: Implement `apply_chunk`, `finish`, `classify` and `retry_delay`**

- **`apply_chunk`:** reads `choices[0].delta.{content, reasoning_content, tool_calls[]}`, `choices[0].finish_reason` and top-level `usage`, using the paths confirmed in M0. Tool calls accumulate in a `BTreeMap<u64, ToolCall>` keyed by `index`: the first `id`/`name` seen wins, and `arguments` fragments are appended. `emitted` is set on the first text or reasoning delta.
- **`classify`:**
  - 401/403 → `Auth`
  - 400 whose body contains the M0 overflow substring → `ContextOverflow`
  - everything else → `Http`
- **`retry_delay`:** retry only on `Http` 429/5xx or `Network`, when `!emitted` and `attempt < 4`. Delay is `1 << attempt` seconds, or `retry_after_s` capped at 60.

- [ ] **Step 4: Implement `ZaiClient`**

- Use a `ureq::Agent` with `http_status_as_error(false)` and a 30s connect timeout. Don't set a global timeout, so streams aren't cut off.
- POST `{base_url}/chat/completions` with:
  - `model`, `messages` (`to_wire`), `stream: true`, `temperature`, `top_p`
  - `tools` only when non-empty
  - `reasoning_effort` when `Some`
  - any field M0 found necessary (e.g. `stream_options`)
- Read the body line by line. Check `cancel` after each line. If it's set, return `Ok(finish(state))` with `interrupted = true`.
- For a retryable error: send `Delta::Notice("<err>; retrying in Ns")`, sleep in 100ms slices while checking `cancel`, then retry.

Spec §11 and §12 define the behavior. The exact control flow:
```
reset cancel; append User; original = text; steps = 0; check_fired = false; edited = false; empty_retried = false; overflow_retried = false
loop {
  if steps == LIMITS.step_limit { if ui.confirm("step limit reached (100) — continue?") { steps = 0 } else { return StepLimit } }
  view = build_view(events); t0 = now
  reply = model.complete(&view, &schemas(), deltas → ui, cancel)

  Err(e) → append Error{kind:"llm", message:e, retry:false}; notice; return Error(…)
  steps += 1
  if reply.interrupted → append Assistant(text + "\n[interrupted]"); cancel every call; append Interrupt{stream}; return Interrupted
  append Assistant{…, latency_ms}
  if no tool calls:
     text empty → if !empty_retried { append Nudge{empty, "(empty response — continue the task, or reply with your answer)"}; empty_retried = true; continue } else { notice; return Error("empty response") }
     edited && !check_fired → check_fired = true; append Nudge{completion_check, completion_check(&original)}; continue
     return Done
  for each call (in order):
     if cancel set → cancel this call and the rest; append Interrupt{tool, call_id}; return Interrupted
     parse args (invalid JSON → !ok result); unknown tool → !ok result
     verdict = perms.check → Ask ⇒ ui.ask(PermissionRequest{tool, summary: tool_summary, detail: mini_diff for edit/write});
         Always ⇒ perms.grant; append Permission
     denied → !ok result ("denied by user" | "denied: not allowed in headless mode (use --mode or --allow)")
     else: ui.tool_start; out = tools::run; capped = cap_output; if truncated → write_artifact("{id}.txt", full) + truncation_note
           append ToolResult; ui.tool_end; edited |= ok && name ∈ {edit, write}
           if out.cancelled → cancel the rest; append Interrupt{tool}; return Interrupted
  repeat guard: the last 3 ToolResults since the latest Nudge{repeat} have the same (name, args, output) → append Nudge{repeat, …}
  compaction check (Task 12)
}
status: ui.status(Status{ctx_tokens: estimate_tokens, budget, tool_calls (this request), elapsed, cached_pct}) on every return path
```
