# Xolotl TB2 Adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run Xolotl on Terminal-Bench 2.0 through Harbor with a custom installed agent. Prove it with a 2-task smoke run, then record a fixed ~15-task baseline with tracked results.

**Architecture:**
- A static musl Xolotl binary is built in Docker and uploaded into each TB2 container by `XolotlAgent`, a Harbor `BaseInstalledAgent`. The agent runs it headless and reports token metrics from Xolotl's JSON event stream.
- Pure helpers live in `xolotl_harbor/core.py` with no Harbor import, so they're unit-testable without Harbor installed.
- `bench/tb2/run.py` wraps build → `harbor run` → result parsing → results JSON + HISTORY row + secrets scan.

**Tech Stack:** Python ≥3.12 for Harbor (uv-managed); the stdlib for our code; Docker Desktop (Linux engine); `rust:1.95-alpine` for the musl build; Harbor 0.23.x.

**Spec:** `docs/superpowers/specs/2026-10-04-xolotl-tb2-design.md`

## Global Constraints

- **Secrets:**
  - The API key comes only from the process env or the Windows User scope (`reg query HKCU\Environment /v ZAI_API_KEY`). It is passed only through `env=` into `exec_as_agent`.
  - Never put it in argv, `--ae`, kwargs, files, logs or prints.
  - After every live run, scan the jobs dir for the key's first 8 characters before writing results.
- **Host:** native Windows with Docker Desktop. If Harbor blocks on Windows, stop and report BLOCKED with the error. The WSL fallback is the user's call.
- **Our code:** Python standard library only. Harbor is a tool dependency, not imported by `core.py`. `agent.py` imports Harbor.
- **Fixed values:**

  | Item | Value |
  |---|---|
  | Dataset | `terminal-bench@2.0` |
  | Model | `zai/glm-5.3-flash` |
  | Default concurrency | `-n 2` |
  | Binary in container | `/installed-agent/xolotl` |
  | Logs | `/logs/agent/{xolotl.jsonl, xolotl.stderr, exit_code, xolotl-home/}` |
  | Timeout | the task's agent timeout − 60 s, floor 60 s, default 900 s |

- **Git:**
  - Branch `feat/tb2`, stacked on `feat/bench`.
  - `bench/tb2/jobs/` is git-ignored.
  - Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Tests:** `py -m unittest bench.tb2.test_tb2 -v` from the repo root. Add `bench/tb2/__init__.py`.

## Review Focus

1. **Instruction quoting.** Shell metacharacters, newlines or unicode in a task instruction must not break or inject into the container command. Pinned by `test_command_base64_roundtrip` (Task 2).
2. **Key leakage into the Harbor job folder** (config, logs, trajectories). Pinned by the post-run secrets scan and `test_secret_scan_detects_planted_key` (Task 3).
3. **An agent exit code or timeout is misread as a task failure or as infra.** Agent exit codes must not become Harbor exceptions, and the verifier decides. Pinned by `test_parse_trial_*` fixtures (Task 3).
4. **The binary isn't static** and crashes on the bullseye or slim images. Pinned by the static check in Task 1, and proven by the smoke run (Task 4).
5. **Xolotl's own timeout vs Harbor's.** Xolotl must stop before Harbor kills the container, so logs are still copied. Pinned by `test_timeout_budget` (Task 2), and observed in the smoke run.

### Task 1: Static Linux build

**Files:**
- Create: `bench/tb2/__init__.py` (empty), `bench/tb2/build_linux.py`, `bench/tb2/.gitignore` (`jobs/`, `__pycache__/`)

**Interfaces:**
- Produces `build_linux.main(argv) -> int`. It prints the absolute binary path on the last line.
- It also exposes `binary_path(repo_root: Path) -> Path` = `<repo>/target/x86_64-unknown-linux-musl/release/xolotl`.

- [ ] **Step 1: Implement `build_linux.py`**

- Check Docker with `docker info`. If it fails, print `Docker Desktop is not running` and exit 1.
- Run the build:
  ```
  docker run --rm -v <repo>:/src -v xolotl-cargo-registry:/usr/local/cargo/registry -w /src rust:1.95-alpine \
    sh -c "apk add --no-cache musl-dev >/dev/null && cargo build --release --target x86_64-unknown-linux-musl"
  ```
  Convert the Windows path for Docker as needed; `D:\X Y` works quoted with Docker Desktop.
- Verify the result is static:
  ```
  docker run --rm -v <repo>:/src rust:1.95-alpine sh -c "ldd /src/<path> 2>&1 || true"
  ```
  The output must contain "not a dynamic executable" or "statically linked", and must not contain "=>".
- Print the path.

- [ ] **Step 2: Build and verify**

Run: `py bench/tb2/build_linux.py`
Expected:
- exit 0;
- the last line is the binary path, and the file exists;
- the static check passes;
- `docker run --rm -v <repo>:/src debian:bullseye-slim /src/<path> --version` prints `xolotl 0.1.0`.

### Task 2: Agent core helpers + `XolotlAgent`

**Files:**
- Create: `bench/tb2/xolotl_harbor/__init__.py`, `bench/tb2/xolotl_harbor/core.py`, `bench/tb2/xolotl_harbor/agent.py`, `bench/tb2/test_tb2.py`

**Interfaces:**
- `core.py` (no Harbor import) produces:
```python
def model_arg(harbor_model: str | None) -> str          # "zai/glm-5.3-flash" → "glm-5.3-flash"; None → "glm-5.3-flash"
def timeout_budget(agent_timeout_sec: float | None) -> int   # max(60, int(t) - 60); None → 840
def run_command(instruction: str, model: str, timeout_s: int) -> str   # the exact shell from spec §5.3, instruction base64-embedded
def metrics_from_jsonl(text: str) -> dict               # reuse bench.run.metrics_from_events + infra reason (import bench.run)
def read_api_key() -> str | None                        # process env, else Windows User scope via `reg query`; never prints
```
- `agent.py` produces `class XolotlAgent(BaseInstalledAgent)`:
  - `name()` → `"xolotl"`
  - `get_version_command()` → `/installed-agent/xolotl --version`
  - `install()` uploads the binary from kwarg `binary` or env `XOLOTL_LINUX_BIN`
  - `run()` calls `exec_as_agent(environment, run_command(...), env={"ZAI_API_KEY": key})`
  - after the run, metrics → context: `n_input_tokens`, `n_cache_tokens`, `n_output_tokens`, `metadata`

  Read Harbor's installed source for exact base-class signatures before coding: `uv tool install harbor`, then inspect `harbor/agents/installed/base.py`.

### Task 3: Wrapper, task sets, secrets scan, README

**Files:**
- Create: `bench/tb2/run.py`, `bench/tb2/smoke.txt`, `bench/tb2/tasks.txt`, `bench/tb2/README.md`, `bench/tb2/results/HISTORY.md` (header only), `bench/tb2/fixtures/…`
- Modify: `bench/tb2/test_tb2.py`

**Interfaces:**
- Produces:
```python
def tasks_hash(names: list[str]) -> str                      # sha256 of sorted names joined by "\n", 12 hex
def parse_job(job_dir: Path) -> list[dict]                   # one dict per trial: task, reward, status (pass|fail|infra_error), exception, tokens, metadata, agent_time_s
def summarize(trials: list[dict]) -> dict                    # pass, total, infra, pass_rate (excluding infra), tokens, median agent time
def history_row(result: dict) -> str                         # | Date | Run | Policy | Tasks | Pass | Tokens (in / out) | Median agent | Note |
def secret_scan(root: Path, key: str) -> list[Path]          # files containing key[:8]; never prints the key
def main(argv) -> int
```
- `HISTORY_HEADER` uses the columns above.

- [ ] **Step 1: Pick the task sets**

Read TB2 task metadata: `difficulty`, `category` and the agent `timeout_sec` from each task's `task.toml`. Get them from the HF dataset or the terminal-bench-2 repo, or from Harbor's local dataset cache after `harbor run --dry-run`.

- `smoke.txt`: 2 easy tasks with 900 s timeouts and few dependencies.
- `tasks.txt`: 15 tasks with this mix:

  | Difficulty | Count |
  |---|---|
  | easy | ~5 |
  | medium | ~5 |
  | hard | ~5 |

  Use varied categories and prefer 900 s timeouts.

Each file starts with a `#` comment header recording the rule and the date. Names are in Harbor's include-flag form; verify with `--dry-run`.
